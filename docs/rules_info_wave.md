# 雷达解析信息波：规则与制作规范摘录（RM2027 V1.0.0，2026-10-15）

来源：
- 《RoboMaster 2027 机甲大师超级对抗赛比赛规则手册 V1.0.0》（下称"规则"）
- 《RoboMaster 2027 机甲大师高校系列赛机器人制作规范手册 V1.0.0》（下称"规范"）

## 1. 机制（规则 5.7.4「雷达解析电磁波」，P113-114）

- 双方雷达基座上放置官方发射源，发射**信息波**（载有对方队伍信息）和**相近频段的干扰波**。
- 原文：「红方广播源/干扰源放置在红方雷达基座，包含有蓝方队伍的信息，反之同理。」
  → 我方要接收的是**己方雷达基座上**的发射源（载有对方信息），离接收天线只有几米，**不是**隔一个场地的对方基座。
  对方基座上的发射源发的是给对方雷达的另一组频点，到我方已很弱。
  → 信号强、干扰波比信息波高约 50 dB，难点是**过载 / 削顶**而不是收不到（见 `rmwave/phy.py` 的标称功率）。
- 队伍可在雷达上自制并安装**天线和解调电路**，解析、识别信息波和干扰波。
- 干扰波分 **3 个难度等级**，难度越高越难解析，**具体参数（频率、调制方式等）后续发布**。

### 信息波内容（对方的）
各机器人位置、血量、剩余发弹量、当前持有增益；队伍剩余经济、总经济；对方各增益点激活状态；装甲受击信息。
具体帧结构见《RoboMaster 2027 机甲大师高校系列赛通信协议》（尚未拿到）。

### 干扰波 / 密钥
- 干扰波不含具体信息，但含一个**对方自定义的 6 位密钥（数字+字母）**。
- 开局及该方干扰波难度变化时，密钥重置为随机值。
- 开局双方干扰波都是 1 级。
- 雷达解析出密钥并发给赛事引擎服务器，成功则**对方后续干扰波难度 +1**（即己方基座的干扰源难度 +1）。
- 当对方干扰波难度 **高于** 己方时：对方雷达即使准确标记己方机器人，也**不产生易伤、不累积"双倍易伤"进度**。
  → 解密钥既是进攻（让对方更难解析我们），也直接废掉对方雷达标记的增益。

### 相关联的机制
- 自适应装甲（规则 5.2）：每发弹丸击中位置（x, y, 区域类别）会"在**雷达无线链路**中发送给攻击方"——即信息波里的"装甲受击信息"。雷达在本方累计命中 ≥10 后可发指令消耗加固机会选中心点，这部分数据可用于决策。
- 雷达识别 / 被标记进度 P / 双倍易伤（规则 5.7.4 前半部分）：信息波里的对方机器人位置可以直接作为雷达标记的坐标来源之一。
- 定位模块离线（规则 5.1.5.4）：对方雷达对该机器人的标记始终视为"准确"。

## 2. 场地（规则 4.2.5 雷达基座，P42）

- 平台 3.4 m × 1.16 m，离地约 2.4 m，四周围栏高 1.1 m，中心对齐战场中轴线。
- 图 4-18 标注了 **[1] 雷达信息波** 和 **[3] 雷达信息波发射面**（发射源在基座上的位置，需要看原 PDF 图）。
- 运算端平台：220 V 市电、一台 1920×1080 仅 HDMI 输入显示器、一根 HDMI 线、一个新国标 5 孔插座。
- 平台旁有传感器数据线槽孔。

## 3. 制作规范中的硬约束

| 条款 | 内容 | 对解析波硬件的影响 |
|---|---|---|
| S22 | 机器人除遥控器、裁判系统、**雷达信息接收装置**外不得搭载无线通讯设备 | 接收装置被明确允许 |
| S23 | 不得产生 0.428–0.438 GHz、2.3–2.55 GHz、3.75–4.75 GHz、5–7.5 GHz 的无线信号干扰 | 只能**接收**，不能发射；注意 SDR/本振泄漏、开关电源辐射，建议用频谱仪自测 |
| S96 | 雷达 = 运算平台端 + 传感器端，**电缆**连接，能显示调试画面 | 接收机→运算端需有线传输 |
| S97 | 运算端：全自动、≤1 个调试遥控器、总功率 ≤750 W、220 V/50 Hz、尺寸 ≤600×350×600 mm | |
| S98 | 传感器端长宽不超出放置平台，高度 ≤1500 mm（建议支架 ≥1.2 m），电压 ≤60 V；**无线电接收装置可与传感器端主体分离**，但长宽仍不得超出平台 | 天线可独立布置 |
| S99 | **运算平台端不得安装或使用无线设备**，无法拆除的须在系统中禁用 | 接收机/SDR 不能放在运算端（含主机自带 WiFi/蓝牙要禁用） |
| S102 | **无线接收装置必须安装在雷达传感器端** | 天线 + 接收前端放传感器支架上 |
| S101/S103/S104 | 传感器端固定在自制支架上放在雷达基座上；信号传输与电源自行解决 | 建议线缆预留 ≥5 m |
| S65 及豁免 | 禁用第三方成品模组，但**雷达运算平台端**可用成品模组/成品系统；其他部分可用满足条件的"市售通用产品"（模组 ≤5000 元，系统 ≤8000 元，非赛事专用） | 市售 SDR（如 HackRF、USRP B 系列等）大概率需按"市售通用产品"判定，留好购买凭证 |
| S110/S112 | 雷达不自带主控，用场地主控；电源管理模块外露，主控接口不接其他设备 | 与裁判系统交互走场地有线网络 |

其它：雷达罚下时多机通信断开（仅能接收、不能发送）；R53 对方不可主动攻击雷达；传感器端需自备防弹保护罩。

## 4. 通信协议（《RoboMaster 2026 高校系列赛通信协议 V2.0.0（20260626）》）

> **开发基准**：2027 版协议尚未发布，本项目目前**以 2026 V2.0.0 协议为准**开发。
> 2027 规则新增的"装甲受击信息"在 2026 协议里没有对应命令码，暂不实现；2027 协议发布后再对照更新。

### 链路与帧格式
- 裁判系统数据链路三种：常规链路、图传链路、**雷达无线链路**（"由裁判系统信号发射源进行数据发送，从雷达接收电磁波并解析信息"）。
- 协议没有写物理层（频率、调制、码率），只给了解调后的数据层。
- 帧格式（与常规链路相同）：

| 字段 | 长度 | 说明 |
|---|---|---|
| SOF | 1 | 固定 `0xA5` |
| data_length | 2 | data 段长度（小端） |
| seq | 1 | 包序号 |
| CRC8 | 1 | 帧头校验，init `0xFF`，见附录一查表 |
| cmd_id | 2 | 命令码 |
| data | n | |
| CRC16 | 2 | 整包校验，见附录一查表 |

### 雷达无线链路命令码（信号发射源 → 雷达，均 10 Hz 持续发送）

| cmd_id | 长度 | 内容 |
|---|---|---|
| 0x0A01 | 24 | 对方英雄/工程/3 步/4 步/空中/哨兵 的 x、y（各 uint16，cm） |
| 0x0A02 | 12 | 对方 1 英雄/2 工程/3 步/4 步/保留/7 哨兵 血量（uint16；未上场或罚下为 0） |
| 0x0A03 | 10 | 对方 1 英雄/3 步/4 步/6 空中/7 哨兵 允许发弹量（uint16，步兵含堡垒储备） |
| 0x0A04 | 8 | 对方剩余金币(u16)、累计总金币(u16)、增益点占领状态位图(u32：补给区、中央高地、梯形高地、堡垒、前哨站、基地、隧道/高地/飞坡/公路场地交互卡) |
| 0x0A05 | 41 | 英雄/工程/3 步/4 步/哨兵 各 7 字节：回血%(u8)、冷却增益(u16)、防御%(u8)、负防御%(u8)、攻击%(u16)；+ 哨兵姿态(u8)；+ 5 台主要状态(u8：0 存活/1 战亡/2 无敌不虚弱/3 无敌且虚弱) |
| 0x0A06 | 6 | 对方干扰波密钥，6 个 ASCII 字母/数字 |

### 雷达相关的常规链路命令
- **0x020E**（服务器→己方雷达，`radar_info` 1 字节）：bit0-1 双倍易伤机会数(≤2)；bit2 对方是否正被双倍易伤；**bit3-4 己方加密等级（=对方干扰波难度，开局 1，最高 3）**；**bit5 当前能否修改密钥**。
- **0x0301 子内容 0x0121 雷达自主决策指令**（8 字节，接收者 ID `0x8080` 裁判系统服务器）：
  - byte0：确认触发双倍易伤计数，单调 +1。
  - byte1：密钥指令类型，`1` = 更新己方密钥，`2` = 提交破解出的对方密钥。
  - byte2-7：6 位 ASCII 密钥。
  - 只能在开局或己方加密等级提高时修改己方密钥；**提交验证后 10 秒内再次提交无效**。
- **0x0305**（雷达→服务器→己方选手端小地图）：对方机器人坐标，≤5 Hz。可直接复用 0x0A01 解出的坐标。
- 雷达/哨兵每秒接收上限 5120 字节；0x0301 上行整体 ≤30 Hz。
- ID：红雷达 9、蓝雷达 109；红方机器人 1–7，蓝方 101–107。
